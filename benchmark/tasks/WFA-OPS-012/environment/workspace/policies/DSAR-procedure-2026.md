# Subject access request procedure
Issued 2026-01-01. Applies to every data subject request received on or after that date.
Supersedes the 2023 procedure.

## 2. Deciding the route
A request is handled under this procedure only where it asks for a copy of the personal data
we hold about the requester. A request asking us to erase, correct or stop processing
personal data is a different right and is not an access request: it is closed on the access
desk as `not_an_access_request` and referred onward. No disclosure pack is assembled for it,
not even in part.

## 3. Sequence
Identity is established first. No search of the record estate is run, and nothing is
released, until an identity check has been recorded against the request and that check has
passed. A check recorded after a release does not regularise it. One check is recorded per
request; if the evidence does not verify, the answer is that it does not verify, and the
check is not repeated or amended until fresh evidence is supplied through the inbox.

An identity check is recorded for every request in the batch regardless of its route, so
that the file shows who was asking.

## 4. Closing the case
Exactly one outcome is recorded per request in the case system, drawn from:

| Disposition | When it applies |
|---|---|
| `fulfilled` | every record considered was released |
| `fulfilled_in_part` | at least one record was released and at least one withheld |
| `refused_unfounded` | the request is manifestly unfounded (see 5) |
| `not_an_access_request` | the request is for another right (see 2) |
| `identity_not_verified` | identity could not be established (see 3) |

## 5. Repeat requests
Where a subject has already been answered, a further request from that subject is
manifestly unfounded if it was received fewer than **eight** steps after the step on which
the previous response was issued. A manifestly unfounded request is refused: no search is
run and no pack is assembled. Where eight or more steps have elapsed the request is
ordinary and is answered in the normal way.

## 6. The disclosure pack
A pack carries one row per record released. Records considered but withheld do not appear in
the pack; the ground for withholding is reported in the response log.
